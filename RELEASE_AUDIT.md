## A. Branch decision

`thesis-submission` at `c1d8afa` was selected as the base because it is the newest and most complete code line. It contains `main` at `d65a202` and adds the Answer EM/F1 migration, Chapter 4 processing/interpretation audit, reasoning-coverage analysis, and associated test.

Pairwise commit audit:

- `origin/master` has three merge commits not reachable from `main`: `aa21b51`, `6c4a162`, and `4d3b4a9`.
- `main` has one commit not reachable from `origin/master`: `d65a202`. `main` is an ancestor of `thesis-submission`, so it has no commit missing from the selected base.
- `thesis-submission` has three commits beyond `main`: `27485cb`, `c0777fd`, and `c1d8afa`.

Exclusive file audit:

- Files present only on `origin/master` are five tracked `__pycache__/*.pyc` files. They are generated bytecode and were deliberately not incorporated.
- No files are exclusive to `main` when all three tips are compared. Relative to `origin/master`, `main` adds the Pizza 100/250 packages, explanation-complexity analysis, and answer-normalization module.
- Files exclusive to `thesis-submission` are the reasoning-coverage script and five outputs, Chapter 4 interpretation audit, SAGE-QA evaluator adapter, and its migration test.

There is no unresolved Git merge conflict and no competing benchmark-generation or dataset implementation that needs merging. The important semantic difference is evaluation lineage: `main` retains a normalized-Jaccard helper and its legacy tests, while `thesis-submission` makes manuscript Answer EM/F1 call the hash-pinned SAGE-QA evaluator. The release candidate retains both only because the helper remains separately tested; manuscript reporting explicitly uses SAGE-QA Answer EM/F1. Generation is generic by dataset name and the selected base already contains both Pizza variants.

No commits were cherry-picked from older branches. No existing branch was changed, deleted, merged, rebased, or force-pushed.

## F. Remaining blockers

1. **Family licensing:** no explicit redistribution license was found in the checked-in Family ontology or located source material. Because Family-derived contexts are embedded in the benchmark ZIP, obtain permission or authoritative license evidence before public distribution.
2. **Evaluator pin drift:** the external SAGE-QA evaluator hash differs from the manuscript-frozen hash. Determine whether to restore/use the pinned evaluator snapshot or scientifically audit and intentionally migrate to the new evaluator before declaring the full test suite green.
3. **Publication metadata:** confirm the complete author/creator list, affiliations, release date, journal citation, and final dataset-license wording. The current files deliberately contain placeholders rather than invented bibliographic data.
4. **Response-level reproducibility:** saved manuscript predictions/results are preserved locally under ignored output paths but are not in the compact release/Zenodo package. Decide whether a separate immutable results archive is required for the journal artifact.
5. **Final security/publication review:** `.env` is ignored and not tracked at current or historical branch tips by that path, but run a dedicated full-history secret scanner and review the exact staged file allowlist before public release.

## Recommendation

**Safe to release v1.0: NO**

The release candidate is technically prepared and its benchmark artifacts validate, but Family redistribution clearance and the evaluator-pin mismatch must be resolved first.
